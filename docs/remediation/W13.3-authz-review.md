# W13.3 BOLA/AuthZ adversarial review

**Change:** `cortex-v2-independent-platform` · **Issue:** #49  
**Scope:** W13.1 opaque resource IDs/BOLA and W13.2 RBAC/ABAC/BFLA  
**Review type:** implementation gate report (2026-07-29)

## Controls inspected

- Authorization is a transport-independent port in `internal/authz`.
- Policy evaluation is default-deny and emits stable, non-resource-revealing
  deny reasons.
- Tenant and workspace context is derived from the verified `domain.Principal`;
  request tenant values are never used as authority.
- Opaque resource resolution is keyed by `(tenant, kind, opaque-id)`.
- `Enforce` is the use-case seam and must run before repository access;
  `NewAuthorizedStore` accepts only an authorized context.
- Audit events contain correlation, actor, action, resource kind, decision and
  reason only; no token, content or secret is recorded.
- PostgreSQL RLS remains the database backstop (`migrations/v2/100_server.sql`).

## Findings

- **CRITICAL:** none found in the implemented W13 seam.
- **WARNING:** Existing repository methods constructed through the historical
  `NewStore(pool, tenant, principal)` compatibility constructor do not enforce
  an `AuthorizedContext` at construction. New server wiring should use
  `NewAuthorizedStore`; removing the compatibility constructor is a breaking
  change and is intentionally deferred to the server wiring wave.
- **SUGGESTION:** Add Docker PostgreSQL negative tests for every graph and bulk
  repository query and run the race/fuzz/coverage/architecture gates in CI.

## Gate verdict
